# 0012 — A single `Include` line in `~/.ssh/config`, on request

Date: 2026-09-16 · Status: accepted · Clarifies the rule "`~/.ssh/config` is never modified" in [`architecture.md`](../architecture.md)

The app keeps its SSH configuration in its data folder and passes it to `ssh` with `-F`. The machine's other clients — `ssh` itself, Zed, the JetBrains IDEs, VS Code and Cursor, Claude Code, Codex — read only `~/.ssh/config` and therefore know none of the app's servers, even though the key is right there, on the laptop. On an explicit gesture from the customer, the app writes **a single line** at the top of `~/.ssh/config`: `Include "<app folder>/ssh/config"`. It removes it the same way. Nothing else in that file is read to be rewritten, or moved.

Why: it is what SSH clients expect — an `Include` at the top, before any `Host` block, so the first value encountered is the app's and no `Host *` of the customer's overrides it. Once the line is there, each of the app's servers answers to its SSH name (`ssh atelier` — a word the user picks next to the name, derived from it by default), with the app's key, `IdentitiesOnly`, the pinned host key and the app's master session, in all the clients at once; the "Open in" buttons on a project's screen depend on it and ask for it first. The alternative, `ssh-add` of the key into the user's agent, does not survive a restart and leaves each client to find the address, the port, the account and the host key.

What we accept: the line is visible and movable by the customer, and the app recognizes it wherever it is. A server name that coincides with a `Host` already declared in `~/.ssh/config` is not written, and the `pupitre-<id>` identifier remains alone. Rule 2 holds: no private key leaves the laptop.

Clarification of 2026-09-18: the included file names the key and the `known_hosts` through `~/.pupitre/<folder>`, a symbolic link (a junction on Windows) that the app keeps pointed at its data folder. JetBrains Gateway reads `~/.ssh/config` with its own parser, which splits `IdentityFile` and `UserKnownHostsFile` on the space in `Application Support`, quoted or not, and then rejects the host key without offering it. The files do not move; it is the written path that changes, and it is rewritten at every startup.
