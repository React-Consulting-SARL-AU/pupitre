One fix in the agent.

## Adding a server

- **Onboarding a freshly installed server no longer stops on "the key could not be laid".** Pupitre 1.0 authorised your device before creating the `dev` account, failed, and "Retry" came back to the same error. The device is now authorised first and opens `dev` as soon as the account exists.

## Known limits

- A server that has not yet accepted the sudo password keeps the old rule, without a password, until it is applied.
- Lose every authorised device and access is put back only from the host's console, with `sudo pupitred keys reset`.
- Docker volumes are not backed up; the app says so when the Docker runtime is installed.
- Whoever can read the bucket reads the manifests, which are in clear: the server's name, the names of the projects, the databases and the folders, the address and branch of the repositories. Never a content, never a secret — those are sealed.
- Whoever holds the S3 key can erase the backups: object versioning or object lock on the bucket is the answer, and the guide says so.
- Lose the passphrase and the backups are unreadable — nobody can recover it.
- The Windows installer is still unsigned: SmartScreen warns at first launch.
