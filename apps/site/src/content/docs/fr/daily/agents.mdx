Pupitre installe les agents ; vous apportez les abonnements. Rien n’est revendu, et aucun de vos jetons n’est stocké sur la plateforme.

## Ce qui est installé

`ai.claude` pose le binaire natif publié par Anthropic, pour cette architecture, et le refuse si sa somme de contrôle ne correspond pas à celle qu’annonce le manifeste de la version. `ai.codex` passe par `mise`, qui épingle et met à jour Codex comme un runtime et le dépose sur le PATH de tous les shells. `ai.cursor` pose le paquet du CLI de Cursor tel que l’installeur de Cursor le fait — sous sa version dans `~/.local/share/cursor-agent`, les commandes `agent` et `cursor-agent` liées depuis `~/.local/bin` — sans exécuter l’installeur. `ai.gemini` et `ai.copilot` passent par `mise` comme Codex, pour Gemini CLI et le CLI de GitHub Copilot. `ai.opencode` pose le binaire statique de la release GitHub d’OpenCode et le refuse si sa somme n’est pas celle que GitHub publie pour l’artefact. `ai.hermes` fait tourner l’agent de Nous Research sur le runtime Python, avec les fournisseurs de modèles que vous configurez.

Les sept s’installent dans le compte `dev`, sur la même machine, et peuvent cohabiter.

## La connexion

`ai.claude`, `ai.codex` et `ai.cursor` se connectent comme partout ailleurs : l’outil affiche une URL, vous l’ouvrez dans votre navigateur, vous approuvez. L’app montre le terminal où cela se passe, si bien que le geste est celui que vous connaissez déjà — il a simplement lieu sur le serveur, et les identifiants y restent. Pour Cursor, la commande est `NO_OPEN_BROWSER=1 cursor-agent login`, sans quoi le CLI tente d’ouvrir un navigateur que le serveur n’a pas ; pour Gemini, `NO_BROWSER=true gemini`, qui affiche l’URL et reprend le code que vous collez. `ai.copilot` passe par `copilot login` et le code d’appareil, sur votre abonnement Copilot. Le niveau gratuit d’un compte Google suffit à Gemini : c’est l’agent à essayer avant de payer quoi que ce soit.

`ai.opencode` n’impose aucun fournisseur : il démarre sur les modèles gratuits qu’il embarque, et `opencode auth login` branche un abonnement Claude, ChatGPT ou GitHub Copilot, ou la clé d’un des fournisseurs qu’il connaît. Le tableau de bord nomme ceux pour lesquels il tient un identifiant.

`ai.hermes` n’a pas ce flux : il parle aux fournisseurs dont vous avez donné les clés à l’installation, et ces clés vivent dans un fichier que seul root peut lire.

## Le contexte qu’ils lisent

Chaque module d’agent écrit le même contexte machine, sous le nom que son outil lit — `CLAUDE.md` pour Claude Code, `GEMINI.md` pour Gemini, `copilot-instructions.md` pour Copilot, `AGENTS.md` pour Codex, OpenCode et Hermes. Cursor fait exception : il n’a pas de fichier de règles global, vos règles vivent dans votre compte, et ce sont les skills qui portent ce que la machine a à dire. Il dit les choses simples qu’un agent qui travaille ici doit savoir : que c’est un serveur Linux et non un poste de travail, où vivent les projets, que les serveurs se pilotent avec la commande `dev` plutôt qu’en les lançant à la main, et que les secrets viennent du gestionnaire de secrets de la machine plutôt que d’un fichier commité.

À côté viennent les skills Pupitre, dans `~/.agents/skills` et dans le dossier propre à l’outil :

- `server-dev` — enregistrer, démarrer et diagnostiquer un projet avec `dev` ;
- `capture` — prendre une capture et répondre par une URL que quelqu’un d’autre peut ouvrir, pas par un chemin local ;
- `branch`, `pr`, `ship` — commiter, pousser, ouvrir une pull request, dans la convention du dépôt.

Claude Code reçoit en plus le sous-agent `git-shipper`. Mettre à jour un module réécrit le contexte et les skills ; le désinstaller reprend ce que le module a écrit et laisse vos conversations, vos identifiants et les skills que vous avez ajoutés.

## Depuis votre propre client

Vous n’êtes pas obligé d’ouvrir un agent depuis Pupitre. L’app Claude accepte une connexion SSH avec la clé que l’app a générée, et l’app ChatGPT lit les alias d’hôte de votre `~/.ssh/config` pour y faire tourner Codex. Dans les deux cas l’agent tourne sur le serveur, dans vos projets, sur les runtimes que les modules ont installés. Tout le réglage est sur [votre propre client](/fr/docs/daily/clients/).

## Où s’ouvre un agent

L’app ouvre un agent dans le dossier du projet, pas dans un répertoire personnel. Les fichiers d’instructions du projet y sont, et les skills ci-dessus aussi.

## Les captures

Avec `ai.browser` installé, un agent pilote Chrome sans interface, range l’image sous `~/shots` et rend une URL servie sur la boucle locale. C’est ce qui lui permet de regarder la page qu’il vient de modifier au lieu de décrire ce qu’il croit avoir fait. Voir [galerie](/fr/docs/daily/gallery/).

## Travailler la nuit

Un agent démarré dans une session `tmux` continue quand vous fermez l’app. C’est tout l’intérêt de la machine : une tâche longue n’a pas besoin que votre portable reste ouvert, et un build n’a pas besoin de vos ventilateurs.

## Ce que Pupitre ne fait pas

Il ne choisit pas de modèle à votre place, ne relaie pas vos requêtes, et ne lit pas vos conversations. Il installe les outils, leur donne le contexte de la machine, les ouvre dans le bon dossier, et vous montre le terminal.
